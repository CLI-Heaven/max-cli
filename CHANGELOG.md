# Изменения

Заметные изменения в `@leemour/max-cli`. Формат — по одному разделу на версию, новое сверху;
номера версий по [семантике](https://semver.org/lang/ru/), то есть до `1.0.0` интерфейс команд
ещё может меняться.

## Не выпущено

### Что нового

- **Что профилю можно: `allow`.** `max work config set allow send,reaction` — профиль только пишет и
  ставит реакции; всё остальное отказывает с кодом `5` до подключения, и ошибка называет команду,
  которая разрешит. Двенадцать имён, от `send` до `sessions`; без списка разрешено всё, как раньше.
  В `max mcp` агент не видит инструментов, которых профиль не разрешает
  ([usage.md](docs/usage.md#что-профилю-можно)).
- **`max messages send … --at <время>`** — отправить позже: сообщение ждёт на сервере MAX и уйдёт,
  даже если компьютер выключен. Время — `2026-09-25T09:00` (местное) или `30m`, `2h`, `1d`.
  **`max messages scheduled <чат>`** — что ждёт отправки. Для MCP — `at` у `max_messages_send` и
  `max_messages_scheduled`. Отменить — в приложении MAX
  ([usage.md](docs/usage.md#отправить-позже)).
- **`max chats read <чат>`** и **`max messages list … --mark-read`** — отметить чат прочитанным,
  только когда вы попросили; собеседник это увидит. Без них чтение по-прежнему ничего не отмечает.
  Для MCP — `max mcp --allow-mark-read` ([usage.md](docs/usage.md#чтение)).
- **`max export messages <чат> --format jsonl|md`** — выгрузить переписку из локальной копии в
  JSONL или Markdown, с `--since` и `--output`. В MAX не ходит; чего в копии нет, называет в stderr.
  Файл из `--output` доступен только вам ([usage.md](docs/usage.md#выгрузка)).
- **`max messages delete <чат> <id…> --allow-dangerous`** — удалить сообщения, до 10 за раз. По
  умолчанию только у вас; с `--for-everyone` — у всех в чате. Без `--allow-dangerous` команда
  отказывает. Каждое удалённое сообщение считается в `sendsPerHour`. Для MCP — `max mcp
  --allow-delete`, только «у меня» ([usage.md](docs/usage.md#удаление)).

### Что исправлено

- **Несколько команд `max` разом больше не теряют вход в локальном кэше.** Раньше две из трёх
  одновременных команд писали «the local record did not take this login» и не сохраняли чаты,
  участников и отметку синхронизации. Теперь вторая ждёт, пока допишет первая.

## 0.7.0 — 24.09.2026

### Что нового

- **`max reactions remove <чат> <id>`** — снять свою реакцию.
- **Группы и каналы** под `max chats`: посмотреть ссылку, вступить, выйти, создать группу,
  добавить и удалить людей, назначить и снять админа, переименовать, поменять настройки, разобрать заявки,
  перевыпустить ссылку. Проходит те же проверки, что отправка
  ([usage.md](docs/usage.md#группы-и-каналы)).
- **`max update`** обновляет `max` тем же менеджером пакетов, которым он поставлен; `--check` только
  говорит, есть ли новее. Раз в сутки человек в терминале видит строку о новой версии; агент и скрипт —
  никогда. Выключается `updateCheck: false` в `defaults`
  ([installation.md](docs/installation.md#обновление-и-удаление)).
- **Автодополнение по Tab** в zsh, bash, fish и PowerShell: `source <(max complete zsh)`. Команды,
  флаги, их значения, чаты и люди из локальной копии — без подключения к MAX
  ([installation.md](docs/installation.md#автодополнение)).
- **`max mcp`** — тот же профиль для агентов по MCP, для клиентов без терминала (Claude Desktop,
  Cursor). Только чтение, пока не запущен с `--allow-send`; отправка проходит те же проверки, что
  `max messages send`. Подключение — [docs/mcp.md](docs/mcp.md).
- **`max mcp --allow-send --confirm-send`** — перед каждой отправкой сервер сам показывает форму: в
  какой чат (название и id) и что. Без «да» ничего не уходит; клиент без форм получает ошибку.
  [docs/mcp.md](docs/mcp.md#подтверждение-формой-от-самого-сервера).
- **`max messages send … --file <путь>`** — фото и файлы; несколько фото — одним сообщением.

### Безопасность

- **Чужой текст больше не управляет терминалом.** Сообщение, имя отправителя, название чата, имя
  файла или реакция с управляющими символами могли стереть строку и напечатать поверх неё то, что
  `max` уже вывел. Теперь такие символы показываются как `\x1b` — в ленте сообщений, в таблицах, в
  сообщениях об ошибках и в подсказках по Tab. JSON не меняется: он и раньше их экранировал.

## 0.6.0 — 24.09.2026

### Что нового

- **`max commands --json`** — все команды, аргументы, флаги и коды выхода одним ответом, для агента
  вместо `--help` по каждой команде. Команды, которые что-то меняют в MAX, помечены `mutates: true`.
  Работает без входа в MAX и даже со сломанным файлом настроек.
- **`max messages send … --reply-to <id>`** — ответ на сообщение.
- **`max messages send … --markdown`** (или `--md`) — `**жирный**`, `_курсив_`, `~~зачёркнутый~~` и `` `код` ``.
  Без флага текст уходит как набран.
- **`max reactions add <чат> <id> <эмодзи>`** — поставить реакцию; прежняя ваша заменяется.
- **Реакции видны при чтении**: `messages list`, `show` и `context` печатают под сообщением
  `👍 3  🔥 1  (you: 🔥)`, в JSON — поле `reactions`. Один дополнительный запрос на страницу, только
  чтение. С `--offline` реакций нет (`null`): они не хранятся.
- **Защита отправки.** Перед каждой `max messages send` проверяются: профиль только для чтения
  (`readOnly`, код `5`), необязательный список разрешённых получателей (`max recipients add`,
  `remove`, `list`, `off`; код `7`) и лимит в час (`sendsPerHour`, по умолчанию 30; код `8`).
  Каждая попытка отправки пишется в журнал без текста — `max sends list`. Что это держит и что
  нет — [security.md](docs/security.md).
- **`max session start qr | qr-chrome | sms | token`** — вход без копирования токена из браузера.
  `qr` рисует QR-код в терминале (узкий терминал — откроет его в браузере); `qr-chrome` и `sms`
  открывают настоящий web.max.ru в отдельном окне Chrome, Chromium, Edge или Brave. Без способа —
  как раньше, токен вручную или из трубы.

## 0.5.0 — 24.09.2026

### Что нового

- **`max messages download <чат> <id> [--output <каталог>]`** сохраняет фото, файлы, видео и аудио
  сообщения. Существующий файл не перезаписывается.
- **`max config set <настройка> <значение>`** и **`max config unset <настройка>`** меняют файл
  настроек без редактора; с `--defaults` — для всех профилей сразу. Новый раздел `defaults` в
  файле действует на каждый профиль, у которого своей настройки нет.
- **`max chats list --unread`** — только чаты с непрочитанным.
- **`max messages list <чат> --after <id|время>`** читает вперёд — то, что пришло после сообщения
  или момента. Подсказка следующей страницы — `--after <id самого нового>`.
- **`max chats show <чат>`** — один чат с участниками, **`max contacts show <человек>`** — один
  человек по id, @username или части имени, с общими чатами. Неоднозначное имя не угадывается:
  команда перечисляет подходящих.
- Всё новое только читает: ничего не отправляет и не отмечает прочитанным.

### Что исправлено

- **`--offline` работает.** Раньше флаг не доходил ни до одной команды: чтение всё равно шло в MAX,
  а `max --offline messages send` **отправлял сообщение**. Теперь чтение отвечает из записанного, а
  отправка и скачивание с `--offline` отказываются.
- **Ошибка в файле настроек объясняется словами**: какая настройка неизвестна и какие есть, что
  допускает значение — вместо сообщения библиотеки проверки.
- **Сломавшийся посреди команды журнал запуска** (`--record`) больше не роняет команду: одна строка
  предупреждения в stderr, ответ и код выхода прежние. Предупреждение видно и с `--quiet`.
- Выпуск идёт из GitHub Actions, и npm прикладывает к версии подтверждение происхождения.

## 0.4.0 — 23.09.2026

### Что нового

- **`max messages show <чат> <id>`** — одно сообщение по id, и **`max messages context <чат> <id>`**
  с `--before` и `--after` — окно вокруг него. Искомое помечено `◀` в ленте и `"anchor": true` в
  JSON. Нет сообщения — «не найдено», а не соседнее.
- **`max skill show`** печатает инструкцию для агента из установленного пакета:
  `max skill show > ~/.claude/skills/max-cli/SKILL.md`.
- **`max config show`** — какой профиль действует и что его выбрало, файл настроек и есть ли он,
  **все профили, включая те, что есть только в состоянии и в файл настроек не записаны**, и каждая
  настройка с тем, откуда она взялась: флаг, переменная, файл или встроенное значение. Если задан
  `MAX_CONFIG_DIR` или его соседи — предупреждает, что запись в ключнице не та, что обычно.
- **Текст сообщения из pipe**: `echo "текст" | max messages send <чат>` — без аргумента с текстом
  он читается из stdin. Так его не видят `ps` и история оболочки, и в нём могут быть переводы строк.
- **`--timeout <срок>`** ограничивает всю команду целиком — подключение, вход и сам запрос, — а не
  ожидание одного ответа.
- **`max doctor`** — от чего зависит каждая команда, без обращения к MAX: откуда берётся токен (сам
  токен не печатается), сколько было входов и когда последний, какие профили входили, схема
  локальной копии против той, что знает эта версия, и какая запись ключницы используется. Отвечает и
  тогда, когда всё сломано: «сессии нет» — это поле ответа, а не ошибка.

### Что исправлено

- **`messages list --before <id>`** больше не требует, чтобы сообщение было прочитано раньше:
  время отправки берётся из самого id.
- **Участники групп показываются по имени**, а не числом. Раньше имя было только у тех, кто есть в
  контактах, и в групповом чате почти все были id. Имена берутся одним запросом и сохраняются, так
  что следующее чтение их уже не спрашивает. То же — для авторов в ответах и пересылках.
- **`bin/release`** дважды останавливался сразу после публикации и не ставил тег. Теперь он
  проверяет версию через `npm view` в обход кэша и ждёт до трёх минут.

### Пропущено в 0.3.0

- ⚠ **`--query` у списков переименован в `--search`** — изменение вошло в 0.3.0, но в его описании
  его не было.

## 0.3.0 — 22.09.2026

### Что нового

- **Переписка читается лентой**: разделитель при смене дня, `время  автор` и текст под ними,
  выровненный по колонке; переносы по ширине терминала. `вы` — свои сообщения, автор без имени —
  его id. `↳` — на что ответ, `↪` — чья пересылка: MAX присылает их целиком, и они сохраняются в
  локальной копии.
- **`-v` и `-vv`** — подробнее: id сообщения, отправителя, чата и адреса вложений; затем всё, что
  известно о сообщении.
- **`--jsonl`** — по объекту JSON на строку, для потока и `jq`.
- **Вложения — ссылками**: `📎 photo`, `📎 photo ×3 1 2 3`, `📎 файл.pdf · 24 MB`. В JSON — `url`,
  `width`, `height`, `title`. ⚠ Ссылка на фото открывается без входа: кому её переслали, тот и увидит.
- **`senderColors: true`** в настройках профиля — свой цвет у каждого автора. По умолчанию выключено.

### Что изменилось

- ⚠ **`-v` теперь подробность вывода, версия — `max -V`.** Строки о запросах на stderr включает
  **`--trace`** — это бывший `--verbose`.
- ⚠ **Локальная копия переходит на схему 4** и при первом запуске собирается заново.

### Что исправлено

- **Имя, подходящее к нескольким чатам**, выводит их списком с id, а в JSON — полем `candidates`.
- **Предупреждение о локальной копии** называло причину словом `Error`. Теперь — какая схема и что
  делать.
- **Подсказка о следующей странице** у `messages list` советовала несуществующий `--page`; теперь
  `--before <id>`.

## 0.2.0 — 22.09.2026

### Что нового

- **`max messages send --silent`** — отправить без уведомления у получателя. Что именно MAX
  делает с этим флагом, пока не наблюдали: для этого пришлось бы написать живому человеку.
- **Токен обменивается при первом входе.** MAX отдаёт в ответ на вход свой токен, и `max`
  теперь сохраняет его в ключницу вместо вставленного из браузера. Это происходит один раз.

### Что исправлено

- **`max session start` больше не портит рабочий токен.** Раньше новый токен записывался до
  проверки, и опечатка заменяла рабочий на мёртвый. Теперь сначала вход, потом запись.
- **Профиль привязан к своему аккаунту.** Токен чужого аккаунта в профиле — отказ с объяснением,
  а не отправка от чужого имени.
- **Подсказка после неясного исхода отправки** называла несуществующую команду `max send`.
- **Сообщения из ответа на вход больше не выбрасываются** из-за неверно описанной формы.

## 0.1.0 — 21.09.2026

Первая версия, которой можно поделиться.

### Что умеет

- **Семь команд против реального MAX**: `session start|end`, `account show`, `chats list`,
  `contacts list`, `messages list`, `messages send`.
- **Профиль — первое слово**: `max personal chats list`. Несколько аккаунтов живут рядом, у
  каждого свой токен, своё состояние и свой кэш. То же самое говорит `MAX_PROFILE`.
- **Токен в ключнице операционной системы**, а не в файле и не в аргументе команды. Своего входа
  по номеру телефона пока нет: `max session start` импортирует токен из официального клиента.
- **Машинный режим**: `--json` кладёт на stdout ровно одно значение JSON и ничего больше; то же
  включается само, когда stdout не терминал. Ошибка уходит на stderr, stdout остаётся пустым.
  Ветвиться можно по коду возврата — таблица в [`docs/commands.md`](docs/commands.md).
- **Диагностика, в которой нет содержимого**: `--verbose` показывает по строке на запрос,
  `--record` кладёт их в каталог запуска на 30 дней, `max runs list|show|path` читает обратно.
  По умолчанию не записывается ничего.
- **Локальная копия**: прочитанное сохраняется рядом; `--offline` отвечает из неё, не подключаясь,
  `max cache clear` её забывает.
- **Настройки** в `~/.config/max-cli/config.json`, с порядком «флаг → переменная окружения → файл
  → встроенное значение». Опечатка в имени поля — ошибка с именем поля, а не молчаливое умолчание.
- **Два рантайма**: Node 22+ и Bun 1.3+, и собранная команда выполняется под обоими в CI.

### Чего не умеет

- **Вход по номеру телефона** — токен берётся из официального клиента.
- **Вложения, реакции, редактирование, группы, истории, звонки** — только текст.
- **Массовая рассылка** — и не появится: это инструмент к личному аккаунту.

### Что стоит знать

- **Протокол MAX неофициальный** и разобран обратной инженерией: это не Bot API. Он может
  измениться без предупреждения, и тогда команда скажет об этом одной строкой на stderr, а не
  сломается молча.
- **Чтение ничего не помечает прочитанным.** «Получить историю» и «отметить прочитанным» — разные
  операции протокола; вторая не отправляется никогда, и это проверяется тестом.
- **Отправка не врёт об исходе.** Если ответ не пришёл — `outcome_unknown` (код `14`), а не
  «ошибка» и не «отправлено»; повтор возможен только с тем же `--cid`.
