# Установка

`max` — одна команда. Ставится как обычный пакет npm, работает под Node и под Bun, ничего не
компилирует при установке и не поднимает никаких фоновых процессов.

## Что нужно

| | |
|---|---|
| **Node 22 или новее** | проверено на 24.19.0; 22 — нижняя граница, она записана в `package.json` |
| **или Bun 1.3+** | проверено на 1.3.14, отдельной проверкой в CI на каждый pull request |
| Linux или macOS | разрабатывается на Linux; Windows никто не пробовал |

Для доступа к ключнице (OS keyring) используется готовый бинарник — собирать ничего не нужно.
Если ключницы на машине нет, токен ложится в файл рядом с настройками, и команда скажет об этом
одной строкой.

## Обычный способ

Запустить, ничего не устанавливая:

```sh
npx @leemour/max-cli --help
pnpm dlx @leemour/max-cli --help
bunx @leemour/max-cli --help
```

Поставить насовсем:

```sh
npm install -g @leemour/max-cli
pnpm add -g @leemour/max-cli
bun add -g @leemour/max-cli
```

Пакет называется **`@leemour/max-cli`**, а команда, которую он ставит, — **`max`**.

Проверка, что всё встало:

```sh
max --version
max --help              # список команд
```

## Из исходников

Нужно, если правите код или хотите версию раньше выпуска.

```sh
git clone git@github.com:leemour/max-cli.git
cd max-cli
pnpm install
pnpm build
```

Дальше — либо положить команду на `PATH`:

```sh
pnpm link --global      # теперь работает просто `max`
```

либо звать по пути, ничего не связывая:

```sh
node dist/bin/max.js --help
```

Проверка, что всё встало:

```sh
max --version
max --help              # список команд
```

Имя без области (`max-cli`) занято чужим пакетом с 2018 года, поэтому область обязательна.

## Куда всё ложится

Три каталога, по соглашениям операционной системы. На Linux:

| Что | Где | Что внутри |
|---|---|---|
| настройки | `~/.config/max-cli/` | `config.json`, и файл с токеном, если ключницы нет |
| состояние | `~/.local/share/max-cli/` | `profiles/<имя>.json`, каталог `runs/` с записями запусков |
| кэш | `~/.cache/max-cli/` | `<профиль>.db` — локальная копия чатов и сообщений |

**Токен хранится в ключнице операционной системы**, а не в файле. В `config.json` для него нет
поля — схема настроек устроена так, что секрет в неё просто некуда положить.

Каждый каталог переопределяется переменной окружения: `MAX_CONFIG_DIR`, `MAX_STATE_DIR`,
`MAX_CACHE_DIR`.

> ⚠ **Переменные переносят и запись в ключнице.** Сессия, сохранённая с `MAX_CONFIG_DIR`, не видна
> команде, запущенной без него: под капотом меняется имя службы, под которым лежит токен. Это
> ровно то, что нужно для временного профиля и для тестов, и ровно то, что однажды стоило владельцу
> получаса с «нет сессии» при живом токене. Либо ставьте переменные всегда, либо не ставьте
> никогда.

## Автодополнение

По Tab дополняются команды, действия, флаги и их значения, а на месте чата или человека — то, что
уже лежит в локальной копии этого профиля. Одна строка в файле настроек оболочки:

```sh
echo 'source <(max complete zsh)' >> ~/.zshrc      # zsh
echo 'source <(max complete bash)' >> ~/.bashrc    # bash
max complete fish | source                         # fish, в config.fish
```

PowerShell — `max complete powershell | Out-String | Invoke-Expression` в профиле.

Tab **никогда не подключается к MAX**: подключение на каждое нажатие — это вход в аккаунт сотни раз
подряд. Пока локальной копии нет, дополняются только команды и флаги. Чат предлагается по id, а
название стоит рядом: название с пробелом дошло бы до `max` двумя словами. Однословное название
предлагается и само.

## Обновление и удаление

```sh
max update            # тем же менеджером пакетов, которым max поставлен: pnpm, npm или bun
max update --check    # только сказать, есть ли новее; ничего не ставит
```

Раз в сутки `max` сам спрашивает npm о новой версии и, если она есть, пишет после команды одну строку
в stderr — только человеку в терминале: не в `--json`, не в трубу, не с `--quiet`, не в `CI`.
Выключается `max config set updateCheck false --defaults`. Сам себя `max` не обновляет никогда.

Из исходников — `git pull && pnpm install && pnpm build`.

Удаление уносит команду, но не данные:

```sh
npm uninstall -g @leemour/max-cli
max session end                        # забыть токен ДО удаления команды
rm -rf ~/.config/max-cli ~/.local/share/max-cli ~/.cache/max-cli
```

`max session end` стирает токен из ключницы. Если сначала удалить команду, запись в ключнице
останется — безвредно, но лежать будет.
