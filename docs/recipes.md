# Рецепты: агент и ваша переписка

Как поручить Claude Code или Codex регулярную работу с MAX: сводку непрочитанного, отчёт по
чату, список долгов и обещаний, напоминания о неотвеченном. В каждом рецепте — запрос агенту,
что ему разрешено и как запускать по расписанию.

## Сначала — один раз

1. `max` установлен, вход выполнен: [installation.md](installation.md), [sessions.md](sessions.md).
2. Агент знает, как работать с `max`, — поставьте ему навык:

   ```sh
   # Claude Code
   mkdir -p ~/.claude/skills/max-cli && max skill show > ~/.claude/skills/max-cli/SKILL.md
   # Codex и Gemini CLI
   mkdir -p ~/.agents/skills/max-cli && max skill show > ~/.agents/skills/max-cli/SKILL.md
   ```

3. Сохраните запросы из рецептов в файлы, например в `~/max-recipes/`. Команды расписания ниже
   читают запрос из файла.

## Что агенту можно

Агент по расписанию работает без вас, поэтому ограничения задаются в настройках, а не в запросе.
Фразу «ничего не отправляй» агент может понять неправильно, запрет в настройках — нет.

**Запрет на уровне агента.** Claude Code в режиме `-p` запускает только команды из
`--allowedTools`. Если `max messages send` в списке нет, агент не может её вызвать:

```sh
claude -p "$(cat ~/max-recipes/morning.md)" --allowedTools "Bash(max inbox:*)"
```

У Codex такого списка нет. Его песочница по умолчанию закрывает сеть и запись файлов, а `max`
нужно и то и другое: подключиться к MAX и сохранить прочитанное в свою копию. Поэтому Codex
запускается с `--sandbox danger-full-access`, а отправку ограничивают настройки `max`.

**Запрет на уровне `max`** действует на любого агента:

```sh
max config set readOnly true           # профиль ничего не отправит
max config set sendsPerHour 5          # или: не больше пяти сообщений в час
max recipients add "Иван Петров"       # и писать только в эти чаты
```

`readOnly` запрещает отправку и вам тоже, пока вы его не выключите: `max config unset readOnly`.
Все попытки отправки, в том числе отклонённые, — `max sends list`.

**Чтение не выдаёт вас.** Ни одна команда в рецептах ниже не ставит отметку «прочитано»:
собеседник не видит, что агент открыл чат.

## Как запускать по расписанию

- **Claude Desktop — запланированные задачи.** Задача запускается на вашем компьютере, поэтому
  ей доступен `max` и ваш вход. Пропущенный запуск (компьютер спал) выполняется один раз после
  пробуждения. Как настроить — [документация Claude](https://code.claude.com/docs/en/desktop-scheduled-tasks).
- **cron и `claude -p`.** Без приложения, на любом компьютере, который включён в это время:

  ```cron
  30 8 * * * claude -p "$(cat ~/max-recipes/morning.md)" --allowedTools "Bash(max inbox:*)" >> ~/max-recipes/morning.log 2>&1
  ```

  Задачи cron запускаются в почти пустом окружении, и в Linux это ломает `max` дважды:

  - **`node: not found`, код 127.** Node, поставленный через nvm, fnm или volta, лежит не в
    системном `PATH`, а cron знает только системный.
  - **`no session for profile "default"`, код 4, хотя вход выполнен.** `max` не может достучаться
    до хранилища паролей и не видит токен. **Не входите заново** — дело не во входе, а в окружении.

  Обе строки — в начало `crontab -e`, со своими значениями: папка — из `dirname "$(which node)"`,
  число — из `id -u`:

  ```cron
  PATH=/home/ivan/.nvm/versions/node/v24.19.0/bin:/home/ivan/.local/bin:/usr/local/bin:/usr/bin:/bin
  XDG_RUNTIME_DIR=/run/user/1000
  ```

  Хранилище паролей доступно, пока вы вошли в систему. Первый запуск проверьте руками и
  посмотрите в журнал.
  Про режим `-p` — [документация Claude](https://code.claude.com/docs/en/headless).
- **cron и `codex exec`.** То же для Codex:

  ```cron
  30 8 * * * codex exec --sandbox danger-full-access "$(cat ~/max-recipes/morning.md)" >> ~/max-recipes/morning.log 2>&1
  ```

  Про режим без диалога — [документация Codex](https://learn.chatgpt.com/docs/non-interactive-mode).
- **Внутри открытой сессии Claude Code** — `/loop` или «напомни в 15:00». Работает, пока сессия
  открыта ([документация Claude](https://code.claude.com/docs/en/scheduled-tasks)).

Облачные задачи Claude (routines) не подходят: они выполняются не на вашем компьютере, и `max` с
вашим входом там нет.

## Утренняя сводка

Пишет в MAX: **нет**. Разрешить: `Bash(max inbox:*)`.

> Выполни `max inbox --new --json`. Сгруппируй сообщения по чатам. Для каждого чата — одна строка:
> кто пишет и чего хочет. Сверху — то, на что нужно ответить сегодня. Рекламу и уведомления
> сервисов сведи в одну строку в конце.

`--new` показывает каждое сообщение один раз: `max` запоминает, где остановился, и следующий запуск
начинает с этого места. Самый первый запуск смотрит на последние 24 часа.

## Недельный отчёт по рабочему чату

Пишет в MAX: **нет**. Разрешить: `Bash(max messages list:*)`.

> Прочитай сообщения в чате «Проект Альфа» за последние 7 дней: `max messages list "Проект Альфа"
> --after` с датой неделю назад в виде `2026-09-17T00:00`, `--limit 200 --json`. Если в ответе
> `"hasMore": true`, читай дальше. Составь отчёт: что решили, кто что взял на себя и к какому
> сроку, какие вопросы остались без ответа. У каждого пункта — дата и автор.

## Кто кому должен

Пишет в MAX: **нет**. Разрешить: `Bash(max messages search:*)`, `Bash(max messages context:*)`.

> Найди в переписке долги, обещания и договорённости. Ищи через `max messages search <слово>
> --json` по словам «верну», «должен», «переведу», «с меня», «договорились», «обещаю». Вокруг
> каждого найденного сообщения читай `max messages context <чат> <id сообщения> --json`. Собери
> таблицу: кто, кому, что, когда договорились и видно ли по переписке, что это сделано.

`max messages search` ищет только в том, что уже было прочитано на этом компьютере, и к MAX не
подключается. Чтобы поиск видел старую переписку, прочитайте её один раз:
`max messages list "Иван Петров" --limit 500`.

## Кому вы не ответили

Пишет в MAX: **нет**. Разрешить: `Bash(max chats list:*)`, `Bash(max messages list:*)`.

> Выполни `max chats list --kind dialog --limit 30 --json`. Для каждого чата, где последнее
> сообщение было за последние 7 дней, прочитай `max messages list <id чата> --limit 5 --json`.
> Покажи чаты, где последнее сообщение не от меня и в нём вопрос или просьба: с кем, о чём и
> сколько дней прошло.

## Черновик ответа

Пишет в MAX: **только после вашего «да»**. Это рецепт для разговора с агентом, не для
расписания.

> Прочитай последние 20 сообщений в чате с Иваном Петровым и предложи ответ на его последний
> вопрос. Не отправляй — покажи мне текст.

Когда вы согласны, агент отправляет сам: `max messages send "Иван Петров" "…"`. Агент без
терминала подключается через `max mcp --allow-send --confirm-send`: перед каждой отправкой вы
видите чат и текст и отвечаете «да» или «нет» ([mcp.md](mcp.md)).

## Похожие сборники

Для MAX готовых рецептов пока нет. Для Telegram есть:

- [Telegram MCP: полное руководство](https://mcp.directory/blog/telegram-mcp-complete-guide-2026) —
  утренний разбор входящих, черновики ответов, сводка по каналу, поиск по нескольким чатам. Запросы
  подходят и для `max`, если заменить инструменты на команды.
- [pioh/tg](https://github.com/pioh/tg) — Claude Code и Codex с личным аккаунтом Telegram: сводка
  раз в N минут, «напомни, если я не ответил маме за 15 минут», наблюдение за людьми и чатами.
- [Gorgias MCP cookbook](https://github.com/gorgias/mcp-cookbook) — рецепты для службы поддержки,
  но хорошо устроены: у каждого сказано, пишет ли он что-то, и что поправить под себя.
