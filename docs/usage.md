# Как пользоваться

Один запуск — одна операция: соединиться, сделать, напечатать, отключиться. Команда не висит
фоном, ничего не слушает и не держит соединение между вызовами.

```sh
max [профиль] [опции] <ресурс> <действие> [аргументы]
```

Полный список команд и опций — [commands.md](commands.md), он собирается из самой программы.

## Первая минута

```sh
max session start        # спросит токен, положит в ключницу
max chats list           # ваши чаты
```

Больше для чтения ничего не нужно.

## Вход

Своего входа по номеру телефона пока нет. `max session start` **импортирует токен**, полученный в
официальном клиенте — в веб-версии `web.max.ru` или в другом клиенте, — и кладёт его в ключницу
операционной системы.

```sh
max session start
MAX token: ▏               # ввод не отображается
```

**Токен не передаётся аргументом**, и это не придирка: аргумент виден в `ps` любому процессу на
машине и остаётся в истории оболочки. Поэтому он либо спрашивается у терминала без эха, либо
читается из трубы:

```sh
pass show max/token | max session start
```

Для CI и разовых запусков есть `MAX_TOKEN` — он старше ключницы, то есть если переменная задана,
берётся она:

```sh
MAX_TOKEN="$(cat /path/to/token)" max chats list
```

Проверить, кто вы:

```sh
max account show
```

Забыть сессию на этой машине:

```sh
max session end
```

`session end` стирает токен **локально** и ничего не говорит серверу MAX: сессия, открытая в
браузере, продолжает жить. Это видно и в ответе — `revokedOnServer: false`.

## Профиль — первое слово

Несколько аккаунтов живут рядом. Профиль называется первым словом, а не флагом:

```sh
max chats list              # профиль default
max personal chats list     # профиль personal
```

Правило простое: **первое слово — это профиль, если оно не совпадает с именем команды.** Поэтому
профиль нельзя назвать `chats` — при создании такое имя будет отвергнуто, с объяснением.

Для целой сессии оболочки удобнее переменная:

```sh
export MAX_PROFILE=personal
max chats list
```

У каждого профиля свой токен, своё состояние и свой кэш.

## Чтение

```sh
max chats list                      # все чаты
max chats list --limit 5            # первые пять
max contacts list                   # люди, с кем есть личный чат
max messages list 0                 # сообщения чата по id
max messages list "Иван Петров"     # или по имени чата
max messages list 0 --limit 50
```

Чат адресуется **id или частью названия**. Если часть названия подходит к двум чатам, команда
откажется угадывать и покажет кандидатов: отправить не в тот разговор — необратимо.

**Чтение ничего не помечает прочитанным.** Протокол разделяет «получить историю» и «отметить
прочитанным»; вторую операцию эта программа не отправляет никогда, и на это есть тест.

## Отправка

```sh
max messages send 0 "текст"
max messages send "Иван Петров" "текст"
```

Отправка — единственная команда, которая что-то меняет. Никаких подтверждений она не просит:
адресат и текст уже написаны в той самой строке, которую вы набрали.

Если ответ не пришёл, команда отвечает `outcome_unknown` (код возврата `14`) — **не «отправлено» и
не «ошибка»**, потому что сообщение могло уйти. В сообщении об ошибке будет `--cid` — номер, с
которым попытку можно повторить, не рискуя вторым сообщением:

```sh
max messages send 0 "текст" --cid 1789784741828
```

MAX схлопывает повтор с тем же `cid` — это измерено, а не предположено
([ARCHITECTURE.md](ARCHITECTURE.md) §6).

## Для скриптов и агентов

```sh
max chats list --json
```

`--json` — это **ровно одно значение JSON на stdout и больше ничего**: ни спиннера, ни галочки, ни
предупреждения. То же самое происходит само, когда stdout не терминал, то есть в трубе и в CI.

Ошибка уходит **на stderr**, а stdout остаётся пустым — так отказ невозможно принять за результат:

```json
{"error":{"code":"authentication_error","message":"no session for profile \"default\" — run `max session start`"}}
```

Ветвиться надо по коду возврата, а не по тексту: текст меняется, код — нет. Вся таблица — в
[commands.md](commands.md), а самые частые: `4` — нет сессии, `6` — не найдено, `9` — таймаут,
`14` — исход неизвестен.

```sh
if ! max messages send 0 "текст" --json > /dev/null; then
  case $? in
    14) echo "могло уйти, повторять только с тем же --cid" ;;
    4)  echo "нужен max session start" ;;
  esac
fi
```

## Что команда делала

По умолчанию **не записывается ничего**. Две отдельные вещи включают диагностику:

```sh
max chats list --verbose      # показать, ничего не сохраняя
max chats list --record       # сохранить, ничего не показывая
```

`--verbose` печатает по строке на запрос — на stderr, поэтому `--json` рядом не ломается:

```text
→ session.login     op 19  seq 2  871 B
← session.login     op 19  seq 2  213ms  48.0 kB  25 chats  6 contacts
```

`--record` кладёт то же самое в каталог запуска и хранит 30 дней:

```sh
max runs list                 # что делалось, новое сверху
max runs show <id>            # один запуск: чем кончился и куда ходил
max runs path <id>            # каталог, для jq и grep
```

**В записи нет содержимого.** Операция, опкод, номер запроса, идентификаторы, байты и
длительности — да. Название чата, имя человека, текст сообщения, номер телефона, токен — никогда,
ни в обрезанном виде, ни в виде хэша.

## Локальная копия

Прочитанное сохраняется рядом, чтобы было чем ответить без сети:

```sh
max chats list --offline      # только из локальной копии, никуда не подключаться
max cache clear               # забыть всё, что этот профиль накопил
```

Обычные команды всё равно спрашивают MAX: ответ на вход и так приносит чаты и контакты, поэтому
отвечать из копии значит сознательно не узнать, что изменилось. `--offline` — это когда сети нет
или когда подключаться не нужно.

## Настройки

Необязательный файл `~/.config/max-cli/config.json`:

```json
{
  "defaultProfile": "personal",
  "profiles": {
    "personal": { "limit": 50, "timeoutMs": 20000, "color": true, "record": false, "keepRunsForDays": 30 }
  }
}
```

Порядок, в котором решается любая настройка: **флаг → переменная окружения → файл → встроенное
значение**. Опечатка в имени поля — ошибка с именем поля, а не молчаливое значение по умолчанию.

**Секрета в этом файле быть не может**: в схеме нет поля, куда его положить.
