# Выпуск версии

Публикуется **с машины сопровождающего**, не из CI. Тег и релиз на GitHub ставятся **после**
публикации, чтобы описывать то, что действительно попало на npm, а не то, что собирались выпустить.

Пакет один: `@cli-heaven/max-cli`, команда — `max`.

## Один раз на машину

Для публикации нужен **гранулярный токен npm с «Bypass two-factor authentication»**
([npmjs.com → Access Tokens](https://www.npmjs.com/settings/leemour/tokens)), с правом записи,
ограниченный этим пакетом. Одноразовый код из приложения pnpm передать не сможет.

Храните его в ключнице, а не в файле:

```sh
secret-tool store --label="npm publish token" service npm account leemour
printf '%s\n' '//registry.npmjs.org/:_authToken=${NPM_TOKEN}' >> ~/.npmrc
```

`~/.npmrc` тогда содержит **ссылку на переменную, а не секрет**: pnpm подставляет `${VAR}` в
пользовательском файле (и намеренно не подставляет в файле проекта).

## Выпуск

**1. Поднять номер.** Единственное место, которое правится руками, — `package.json`:

```sh
# отредактировать "version" в package.json
pnpm version:sync          # перенести в src/version.ts
pnpm version:check         # убедиться, что они совпадают
```

До `1.0.0` интерфейс команд ещё может меняться, и номер это говорит честно.

**2. Дописать [`../CHANGELOG.md`](../CHANGELOG.md)** — для человека, а не из `git log`: что
появилось, что сломалось, чего по-прежнему нет. Проставить дату вместо «не выпущено».

**3. Прогнать всё.** В этом порядке:

```sh
pnpm install
pnpm lint && pnpm typecheck && pnpm test
pnpm build && pnpm smoke:bun
pnpm generate && git diff --exit-code
pnpm version:check
```

`pnpm generate` с последующим `git diff` — это проверка, что [`commands.md`](commands.md) и
[`protocol.md`](protocol.md) описывают ту версию, которую вы выпускаете, а не предыдущую.

**4. Посмотреть, что уедет.**

```sh
npm pack --dry-run
```

Внутри должны быть только `dist`, `package.json`, `README.md` и `LICENSE`. Ни `docs_ai/`, ни
журналов, ни фикстур. Если появилось что-то ещё — разбираться до публикации, а не после.

**5. Опубликовать.**

```sh
NPM_TOKEN="$(secret-tool lookup service npm account leemour)" pnpm publish --access public
```

Область обязательна: `--access public`, иначе scoped-пакет уйдёт приватным.

**6. Проверить с чужой стороны** — не из репозитория:

```sh
cd /tmp && npx @cli-heaven/max-cli@latest --version
```

**7. Тег и релиз**, теперь, когда известно, что именно опубликовано:

```sh
git tag -a v0.1.0 -m "0.1.0"
git push origin v0.1.0
gh release create v0.1.0 --notes-from-tag
```

## Первый выпуск: что снять

⚠ На npm с 19.09.2026 лежит `0.0.0` — заготовка. И [`../README.md`](../README.md), и
[`installation.md`](installation.md) предупреждают об этом прямым текстом.

**В день публикации `0.1.0` оба предупреждения убираются**, иначе документация начнёт врать в
обратную сторону — и `installation.md` переходит с установки из исходников на обычную.

## Если что-то пошло не так

npm не даёт переопубликовать ту же версию. Правильный ответ — **следующий номер**, а не попытка
починить опубликованный: `npm unpublish` работает только в первые 72 часа и ломает всех, кто уже
успел поставить.

Если опубликовано что-то не то — выпустите патч-версию и, если дело серьёзное, пометьте прошлую
как нерекомендуемую:

```sh
npm deprecate @cli-heaven/max-cli@0.1.0 "содержит X, поставьте 0.1.1"
```
