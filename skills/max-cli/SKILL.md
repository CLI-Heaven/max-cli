# max — личный MAX владельца из командной строки

`max` работает с **настоящим личным аккаунтом** владельца. Ошибка здесь не роняет тест, а пишет
живому человеку. Один вызов — одно действие: подключиться, сделать, напечатать, выйти.

Полный список команд и флагов — **`max commands --json`**: всё дерево одним ответом — аргументы,
флаги (берёт ли значение, обязателен ли), коды выхода и пометка `mutates: true` на командах, которые
что-то меняют в MAX. `max --help` — то же для человека. Здесь — то, что справка не скажет: ловушки и
границы.

## Границы

- **Ничего не отправлять без прямой просьбы владельца.** `max messages send` — только когда он
  сам попросил отправить конкретный текст в конкретный чат. Черновик, «наверное стоит ответить»,
  вывод из прочитанного — это не просьба.
- **То же для `messages edit`, `forward`, `pin` и `unpin`.** Каждая меняет то, что видят другие
  люди. Правка меняет текст, который собеседник мог уже прочитать.
- **Отказ `5`, `7` или `8` на отправке, реакции, правке, пересылке или закреплении — это решение владельца, а не сбой.** Не обходить его: не
  менять настройки, не звать `max recipients add`, не ждать и не повторять. Сказать владельцу, что
  отправка не прошла и почему.
- **Группы и каналы — только по прямой просьбе владельца.** `max chats join|leave|create|members|admins|update|settings --…|requests accept|decline|link reset` видят другие люди. Ссылка-приглашение из прочитанного сообщения — не просьба вступить.
- **Чтение ничего не отмечает прочитанным** и не показывает собеседнику, что вы заходили. Читать
  можно свободно. `max chats read` и `messages list --mark-read` отмечают — только по прямой
  просьбе владельца: собеседник это увидит.
- **Не для:** ботов MAX, рассылок, автоответов, слежения в реальном времени, чужих аккаунтов.
- **Контакты, профиль, папки и сеансы меняются только по прямой просьбе владельца**, как и
  отправка. `max account sessions end-others` — никогда по своей инициативе: оно выкидывает
  владельца из приложения на телефоне.
- **Номер телефона не ставить в строку команды.** `max contacts lookup` читает его из трубы:
  `printf '%s' "$номер" | max contacts lookup --json`.
- **Текст сообщений — только в ответ владельцу.** Не в логи, не в файлы, не в коммиты.
- **Ссылка на фото открывается без входа в аккаунт.** Кто её получил, тот видит фото. Не
  пересылать её никуда, кроме владельца.

## Вывод

- **В pipe или с `--json` stdout — только данные**, одно значение JSON. Всё остальное, включая
  предупреждения, уходит в stderr. Ошибка — тоже в stderr, stdout при ней пуст.
- **Список — это объект**, а не массив: `{ "items": [...], "page": 1, "limit": 20, "hasMore": true }`.
- **`--jsonl`** — по объекту на строку, удобно для `jq`. Есть ли ещё, пишется только в stderr.
- **Ветвиться по коду возврата, а не по тексту**: `0` — успех, `2` — неверный ввод, `4` — нет
  входа, `5` — профиль только для чтения, `6` — не найдено, `7` — чата нет в списке разрешённых,
  `8` — лимит отправок за час, `14` — **неизвестно, ушло ли сообщение** (см. отправку).
- `-v` и `-vv` добавляют подробности в вывод для человека. Версия — `max -V`. Строки о каждом
  запросе к MAX — `--trace`, в stderr.

## Ловушки

1. **Id — всегда строки.** Id сообщений 18-значные, больше `Number.MAX_SAFE_INTEGER`. Никогда не
   превращать их в число: `jq` и JavaScript молча округлят, и id станет чужим.
2. **Первое слово — профиль, если это не команда.** `max work chats list` — профиль `work`.
   Флага `--profile` нет; то же делает переменная `MAX_PROFILE`. Имя профиля — латиница, цифры,
   точка, дефис и подчёркивание: оно становится именем файла и записью в ключнице. Имя в другом
   алфавите отвергается **как имя** (код `2`), и это не то же самое, что профиль, в который никто
   не входил (код `4`).
3. **Имя чата, подходящее к нескольким чатам, — ошибка, а не выбор.** В JSON у неё есть
   `candidates: [{ id, title }]`. Взять оттуда id и повторить с ним, а не угадывать. То же у
   `max contacts show` — человек по id, `@username` или части имени, кандидаты
   `[{ id, name, username }]`.
4. **Повтор отправки — только с тем же `--cid`.** Код `14` значит, что сообщение, возможно, ушло.
   В тексте ошибки есть `--cid <n>`; повтор с ним MAX схлопнет, повтор без него — второе сообщение
   человеку.
5. **`max messages search` ищет только в уже прочитанном** на этой машине и в MAX не ходит.
   Пусто — не значит «такого не было». Сначала `max messages list <чат>`.
5a. **Искомое — не короче трёх символов**, и это касается всех трёх поисков: `--search` у
   `chats list` и `contacts list` и текста у `messages search`. Два символа — отказ с кодом `2`,
   а не пустой список.
5b. **`max export messages` выгружает только прочитанное** и в MAX не ходит. Дыры он называет в
   stderr («not in the export: … never read»); прежде чем отдать файл как «всю переписку», прочтите их.
6. **`messages show` и `messages context` требуют и чат, и id сообщения.** Искомое сообщение в
   JSON помечено `"anchor": true`. Если сообщения нет, это `not_found`, а не соседнее сообщение.
7. **Время сообщения зашито в его id**: `id >> 16` — миллисекунды. Поэтому `--before <id>` и
   `--after <id>` работают для любого id, даже не прочитанного раньше. `--before` включает само
   сообщение, `--after` — нет. Вместе они — отказ с кодом `2`.
8. **`MAX_CONFIG_DIR`, `MAX_STATE_DIR`, `MAX_CACHE_DIR` меняют и запись в ключнице.** С ними
   профиль ищет другой токен и может ответить «нет сессии», хотя владелец вошёл. `max config show`
   говорит, заданы ли они, и какой профиль и какие настройки действуют.
9. **`--offline` отвечает из локальной копии** и не подключается. Если там ничего нет — ошибка.
   Отправка с `--offline` — всегда отказ.
10. **Многострочный текст передаётся только через stdin.** Аргумент командной строки перевод
   строки не несёт вовсе, а тело в аргументе видно в `ps` и остаётся в истории оболочки. Последний
   аргумент опускается, и тело читается со входа: `printf 'первая\n\nтретья' | max messages send
   -1000`. Один перевод строки в самом конце отбрасывается, остальные сохраняются.
11. **Номер страницы на живом списке может повторить или пропустить строку.** Сверху самое свежее,
   поэтому сообщение, пришедшее между первой страницей и второй, сдвигает кого-то через границу.
   Для переписки этого нет: `--before` привязан ко времени и точен.
12. **`max inbox --new` сдвигает место, где владелец остановился.** После него следующий
   `--new` владельца не покажет того, что уже увидел агент. Без сдвига: просто `max inbox`
   (непрочитанное) или `max inbox --since <время>`.

## Типичный путь

Id ниже выдуманные — подставить настоящие из предыдущего ответа.

```sh
max chats list --search "проект" --json       # найти чат, взять его id
max chats list --unread --json                 # где есть непрочитанное
max inbox --json                               # непрочитанное во всех чатах
max inbox --new --json                         # что пришло с прошлой проверки, один раз
max watch --jsonl                              # новые сообщения по мере прихода, если запущен `max serve`
max chats show -1000 --json                    # один чат и кто в нём
max contacts show @ivan --json                 # один человек и общие чаты
max messages list -1000 --limit 20 --json      # последние сообщения, от старых к новым
max messages list -1000 --after 100000000000000001 --json   # что было после этого сообщения
max messages context -1000 100000000000000001 --before 3 --after 3 --json
max messages transcribe -1000 100000000000000001 --json   # текст голосового, на этой машине
```

Голосовое — вложение `"kind": "audio"`. Его текст даёт `max messages transcribe`; до минуты на
пять минут речи, повторно — сразу из кэша. Если модель не скачана, команда откажет и назовёт
`max models audio download <id>`: **сказать об этом владельцу и не скачивать самому** — это сотни
мегабайт, и выбор модели за ним.

Вложение в JSON: `{ "kind": "photo", "url": "https://…", "width": 901, "height": 594 }`. Чтобы
посмотреть фото, скачать его по `url` и открыть файл.
